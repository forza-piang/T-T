# TT Planner 国内适配分支

本分支由 forza-piang 维护，基于 [bhxnms/T-T](https://github.com/bhxnms/T-T) v0.8.1，保留原项目历史、署名及 [AGPL-3.0 许可证](LICENSE)。国内适配功能版本为 `0.8.1-cn.7`，功能修改于 2026-09-28，公开发布配置整理于 2026-09-30。

上游基准提交：`e068e97ca67015233f74d6998970482a3d5700f9`。本分支尚未合并后续上游版本。

## 与上游的差异

- 高德 JS 安全密钥使用需登录的同源服务端代理；修复地图视野与分类探索的联动，完善坐标转换及地点表单适配。
- 桌面端双击地点列表可重新定位地图；高德地图提供“使用我的当前位置”，仅点击时申请浏览器定位，显示精度范围及失败提示。
- 地点导航保留高德、苹果和谷歌地图。
- 旅行和列表封面仅保留本地上传入口，移除 Unsplash 搜索入口。
- 假期日历内置中国大陆 2026 年放假和调休上班安排；桌面端、手机端和年假计算同步适配。
- 费用表单支持付款截图识别、字段预览和分类建议，桌面端与手机端均可使用。用户核对后填入表单，仍需点击保存才会新增支出。
- 默认勾选 MiniMax M3；取消勾选使用服务端本地 Tesseract OCR。分类不明确时不覆盖现有选择，所有识别结果均可手动修改。

这是针对家庭使用场景的定制分支，并非完全去除海外服务的版本。其他模块仍可能依赖上游的 Google、OSM、OSRM 等服务。

## 从源码部署

需要 Git、Docker 和 Docker Compose。以下命令只用于**新的部署目录**；已有实例应先备份数据、上传文件及加密密钥，检查端口与挂载路径后再升级。

```sh
git clone --branch cn-adaptation https://github.com/forza-piang/T-T.git
cd T-T
cp .env.example .env
```

编辑 `.env`，设置管理员邮箱与密码，并将 `ENCRYPTION_KEY` 替换为 `openssl rand -hex 32` 生成的值。不要把填入凭证的 `.env` 提交到 Git。已有实例必须保留原来的加密密钥。

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.cn.yml build app
docker compose --env-file .env -f docker-compose.yml -f docker-compose.cn.yml up -d --no-build app
```

国内适配覆盖文件使用本地构建镜像 `tt-planner:0.8.1-cn.7`，不会拉取原版镜像替代它。首次构建需要下载基础镜像及依赖。默认主机端口继承上游配置，为 3000，可通过 `HOST_PORT` 修改。

生产访问应配置 HTTPS 反向代理；在 `.env` 设置自己的 `APP_URL`、`ALLOWED_ORIGINS`，按实际代理层数设置 `TRUST_PROXY`，并开启 `FORCE_HTTPS=true`。本仓库不包含任何已配置的域名、隧道令牌或生产数据。参阅上游 [反向代理说明](wiki/Reverse-Proxy.md)。

首次登录后，在管理后台按需关闭公开注册，使用“管理 → 用户 → 创建用户”为家人添加普通账号；再将账号加入对应旅行。公开注册、地图偏好等实例设置保存在数据库中，不会随源码自动复制。

## 高德配置

- `AMAP_JS_API_KEY`：Web 端（JS API）Key，用于加载地图；它会出现在浏览器中，应配置自己的域名限制。
- `AMAP_SECURITY_JS_CODE`：与 JS Key 配套的安全密钥，仅供服务端代理使用。
- Web 服务 Key：通过管理后台保存，用于地点搜索、详情及路线。不要把 Web 服务 Key 当作 JS Key。

在管理后台启用高德搜索，并在地图设置中选择高德底图。详见 [高德说明](wiki/zh/AMap.md)。代理只接受已登录用户，匿名分享页不使用此代理。定位需要安全上下文和浏览器授权，具体精度与可用性取决于设备及定位服务。

## 付款截图识别

`MINIMAX_RECEIPT_API_KEY` 是专用服务端配置，不与预订识别的模型设置共用。目前实现固定使用 `https://api.minimax.cn/v1/chat/completions` 与 `MiniMax-M3`，接受 `sk-cp-` 类型的 Coding Plan Key。接口和套餐支持范围可能变化，部署者需以自己的账号权限为准。

该配置支持纯文本 Key，或使用本应用加密机制产生、与实例 `ENCRYPTION_KEY` 匹配的 `enc:v1:` 值。凭证仅放在受保护的服务器环境配置中，不能写入前端或镜像。

- 勾选 MiniMax 时，点击识别会将处理后的截图经服务器发送给 MiniMax，并使用账号的套餐额度。请先裁剪无关个人信息。
- 没有配置 MiniMax 时，默认选项会提示不可用；可取消勾选改用本地 OCR，不会自动改用其他付费接口。
- 本地识别只调用服务器的 Tesseract，使用 `chi_sim+eng` 语言数据；本分支 Dockerfile 已包含这些依赖。
- 识别支持 PNG/JPEG，前端原图最大 12 MB 并会缩放；服务端接收图像最大 4 MiB。识别接口不自动保存截图，也不直接创建支出；“添加收据”是独立的保存操作。
- 识别可能失败或出错，付款状态、金额、日期和分类均应核对。缺失或含糊字段不会补造。

## 版本与验证

发布准备开始时，104 个修改/新增文件与 `cn.7` 部署归档逐字节一致；发布整理期间仅清理了两个源码文件末尾的多余空行，并更新相关文档，未改变功能。此前在隔离环境中验证了地图、导航、封面、日历和截图识别相关逻辑；`cn.7` 地图交互回归共 549 项测试通过，客户端类型检查与生产构建通过。这些是该版本已有的验证记录，不代表 Fork 的全量 CI 已运行。

公开发布整理只新增部署配置、构建依赖和说明，没有数据库迁移。2026 年以后的节假日尚未内置；本分支并未提供完全离线的地图或识别服务。采用本地部署时，服务端仍需访问所配置的地图或模型接口。

## 选择性跟进上游

Fork 的原有默认分支保留上游历史；国内适配使用 `cn-adaptation`。首次设置上游远程：

```sh
git remote add upstream https://github.com/bhxnms/T-T.git
git fetch upstream --tags
```

每次更新先从国内适配分支建立临时分支，再选择合并一个已审阅的上游版本，或 `cherry-pick` 独立提交。先检查依赖和数据库迁移，再验证、合入、打标签及部署。不要对定制分支直接使用强制同步或覆盖操作。

推送 GitHub 不会自动更新任何现有部署。上游自带的镜像发布工作流仍指向原作者仓库；本次仅发布源码，不运行它们，也不提供新的容器仓库。后续如需发布自己的镜像，应先单独调整工作流。

其余功能和开发命令参阅 [原项目中文说明](README.zh-CN.md)。
